# 12 · 审计、敏感信息与安全

## 1. 审计日志

**audit_logs**（按月分区）

| 字段                           | 说明                                                                                                          |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| id                             | UUID v7                                                                                                       |
| user_id / identity_id / org_id | 操作人与身份                                                                                                  |
| school_id                      | 涉及学校，可空                                                                                                |
| action                         | 如 `auth.login`、`identity.select`、`role.update`、`school.student.update`、`export.create`、`sensitive.view` |
| target_type / target_id        |                                                                                                               |
| changes                        | jsonb，字段级变更 `{ field: [before, after] }`，敏感字段只记“已修改”                                          |
| ip / user_agent / trace_id     |                                                                                                               |
| created_at                     |                                                                                                               |

必须记录：登录与退出、选择身份、改密与重置、角色与档位变更、部门与范围变更、身份增删、代理商授权、学校服务变更、导出、查看敏感信息、删除与恢复、学年切换、学校库开通与销毁。

编号规则修改记录 `number.rule.update`，保存前后前缀、位数和重置周期；正常取号登记在 `number_issues`，随业务事务一起提交，不为每次取号重复写管理操作审计。

接口：`GET /audit-logs?action&userId&from&to&page`（`system:audit:view` 全平台；`org:audit:view` 本组织）；详情页“变更历史”页签按 target 查询（P1）。

### 审计基础实施约定（T-130）

- 现有已上线业务的审计统一通过 `infra/audit` 的事务写入器处理；`@Audit()` 装饰器只整理审计内容，不创建独立事务，不在 HTTP 成功响应后补写。调用方必须传入业务事务，审计失败与业务修改一起回滚。
- 新写入的整对象 `before/after` 快照转换为 `{ field: [before, after] }`，相同字段不重复记录，新增或清空用 `null` 表示。已经采用字段差异的记录继续保留；登录结果、修改原因、菜单定位等事件说明保留。调用方只提供需要留痕的业务字段，不传整个请求或令牌。菜单快照只比较显示名称、顺序、显隐，不把只读目录属性误记为删除。
- 对标准敏感字段名（密码及哈希、手机号及密文/哈希、邮箱、证件号码、访问/刷新令牌及密钥等）递归去值，仅记“已修改”；不保存敏感前后值。密码长度等系统参数属于普通规则数值，正常记录数值变化。新增敏感业务字段时须同时登记去值规则和测试。已有历史审计不覆盖重写。
- 退出、改密按服务端当前会话关联到账号、身份与组织；未选择身份的账号级会话留空身份/组织，不伪造归属。已停用身份仍保留该次会话的审计归属，外部传入的身份标识不用于归属计算。
- 审计分区按上海时间每月划分，保留兜底分区。后端启动及每日准备本月与未来两个月的分区，同时将兜底中的已有月份完整迁入对应月分区。维护在同一事务内锁定父表，搬迁、建表、挂接一起提交或回滚，多个实例串行处理；锁等待最多5秒。定时维护失败保留兜底写入并记录错误，次日重试；停机时清理定时器并等待在途维护。
- 本阶段验收现有登录/退出/改密、身份、组织、角色模板与自定义角色、部门与负责范围、成员与额外负责、学校档案、学年学期、字典、编号、系统参数、区划和菜单业务。代理授权、学校服务、导出、敏感全文查看等未实现业务随所属任务接入，不能据此声称全部未来动作已经留痕。查询筛选归 T-133，保留清理归 T-134，平台操作记录前端归 T-164。

### 审计查询实施约定（T-133）

- `GET /api/v1/audit-logs` 为只读分页接口。`scope=organization`（默认）要求 `org:audit:view`，只查当前身份所在组织；`scope=platform` 要求公司身份且拥有 `system:audit:view`。两项权限不能互相替代，请求不能传入其他组织扩大边界。
- 支持动作 `action` 精确匹配、操作账号 `userId`、带时区的 `from/to`（均含边界）、`createdAt:asc/desc` 稳定分页。按对象历史查询须使用 `targetType`，指定 `targetId` 时必须同时提供类型；查询结果与计数始终使用同一组织边界，没有可见记录时返回空列表。
- 账号级审计的身份与组织为空，只在全平台中可见；不把账号后来选择的身份补到历史记录上。归属使用日志原有标识，实体停用或软删除不排除日志。操作人、组织和学校名称为关联实体的当前名称，不宣称保存了历史姓名、历史角色或历史名称快照，关联不存在时返回空名称。
- 返回真实动作、目标类型、变更、来源地址与时间，所有行 `allowedActions=[]`。读取旧记录时也执行标准敏感字段去值，不修改原始记录；未记录的操作结果不推断为成功。没有新增修改、删除或导出日志接口，异步导出仍依赖 T-114。
- 每次查询重新加载身份权限快照，查询结束后再校验修订；读取期间发生撤权则丢弃旧结果并重查，持续变更最多重试三次后返回503。行与总数在同一只读、可重复读事务内获取。

## 2. 敏感信息

| 字段   | 存储                         | 默认显示             |
| ------ | ---------------------------- | -------------------- |
| 证件号 | AES-256-GCM 加密 + HMAC 哈希 | `330***********1234` |
| 手机号 | 加密 + 哈希                  | `138****5678`        |
| 邮箱   | 明文（登录需要）             | `z***@qq.com`        |

- 需要身份拥有对应功能模块的 `sensitive`（查看敏感信息）动作才能点击显示全文，每次写 `sensitive.view` 审计。
- 加密数据格式：`v{keyVersion}:{iv}:{ciphertext}:{tag}`。
- 账号手机号的 `users.phone` 为 `text` 密文；`phone_hash` 为 HMAC-SHA-256 的 64 位小写十六进制字符串（`varchar(64)`），用于登录与查重。两列同时为空或同时有值；对未删除账号的哈希建立唯一索引。

## 3. 密钥管理

- 密钥（JWT 签名、字段加密、HMAC）只由部署环境注入（Docker secrets 或环境变量），不进代码库。
- 支持多版本：新数据用最新版本；读取按版本号选择密钥；后台任务逐步把旧版本数据重加密。
- HMAC 密钥不轮换（轮换会导致查重失效）；如需轮换需全量重算索引，列为运维操作。

## 4. 安全基线

| 项     | 做法                                                                  |
| ------ | --------------------------------------------------------------------- |
| 传输   | 全站 HTTPS，HSTS                                                      |
| 响应头 | CSP、X-Content-Type-Options、X-Frame-Options（DENY）、Referrer-Policy |
| 密码   | argon2id                                                              |
| 限流   | 登录 10 次/分钟/IP；查重 30 次/分钟/身份；全局 300 次/分钟/身份       |
| 上传   | 扩展名白名单、大小上限、文件头校验                                    |
| 注入   | 全部参数化查询；schema 名白名单校验                                   |
| 依赖   | CI 运行依赖漏洞扫描与镜像漏洞扫描，高危阻断合并                       |
| 日志   | 不记录密码、令牌、证件号明文                                          |

T-017 使用 Redis 在实例间共享 60 秒限流窗口。全局每个身份最多 300 次，匿名请求按连接 IP 计数。登录入口 `POST /api/v1/auth/login` 另按连接 IP 限制 10 次。应用直接读取连接地址。反向代理场景需在部署任务中配置可信代理策略。后续认证 Guard 需先将已验证的 `identityId` 写入 CLS，再执行身份维度限流。超限返回 HTTP 429、90005 和 `Retry-After`。Redis 不可用时受限流保护的路由返回 503，健康检查仍可用。

JSON 与 URL 编码表单请求体上限为 1 MiB，超限返回 HTTP 413 和 90006。文件上传由 T-111 配置独立限制，查重专用限流由 T-100 接入。

## 5. 数据保留

| 数据               | 保留                             |
| ------------------ | -------------------------------- |
| 审计日志、登录日志 | ≥ 6 个月（默认 12 个月）         |
| 回收站             | 30 天                            |
| 导出文件、导入预览 | 24 小时                          |
| 已处理待办         | 1 年                             |
| 已读消息           | 6 个月                           |
| outbox 已投递事件  | 7 天                             |
| 已发系统编号登记   | 永久保留，防止规则变化后重复分配 |

清理任务每天 02:00 执行，删除操作写审计。

## 6. 验收标准

- 任意一次导出都能在审计日志中查到导出人、条件与行数。
- 数据库中证件号、手机号为密文；轮换加密密钥后旧数据仍可读取。
- 安全响应头在所有页面存在。
- 应用日志中搜索不到任何证件号明文。
