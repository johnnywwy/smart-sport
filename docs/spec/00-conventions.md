# 00 · 通用约定

所有规格共同遵守的约定。各规格中不再重复。

## 1. 接口

| 项         | 约定                                                                     |
| ---------- | ------------------------------------------------------------------------ |
| 前缀       | `/api/v1`                                                                |
| 风格       | REST；资源名用复数短横线，如 `/api/v1/academic-years`                    |
| 学校内资源 | 一律 `/api/v1/schools/:schoolId/...`，并标注 `@SchoolScoped()`           |
| 请求校验   | 每个接口的 body、query、params 都有 `packages/contracts` 中的 Zod schema |
| 文档       | 由 Zod schema 生成 OpenAPI，开发环境 `/api/docs` 可访问                  |

开发环境可从 `/api/docs/openapi.json` 下载 OpenAPI 文档。路由参数用 `ZodRequest` 绑定共享对象 schema，响应文档用 `ApiZodResponse` 声明。业务响应 schema 应包含统一响应封装。

### 1.1 响应格式

```json
{ "code": 0, "message": "ok", "data": {}, "traceId": "0193..." }
```

- 成功 `code = 0`；失败时 `code` 为 5 位错误码，HTTP 状态码同时表达类别（400/401/403/404/409/422/429/500）。
- 服务端为每个请求生成 UUID v7，并通过 `X-Trace-Id` 响应头返回。业务响应体的 `traceId`、CLS 请求标识和 pino 日志中的 `traceId` / `req.id` 使用同一个值。

- 成功响应的 `message` 为 `ok`，无返回值时 `data` 为 `null`。204 响应无响应体。
- 字段校验错误使用点分路径（如 `items.0.name`）。整条请求的格式错误使用 `_request`。无详情的错误使用 `data: null`。
- 健康检查保留独立响应格式，通过同一响应头关联日志。

### 1.2 分页、排序、筛选

| 参数       | 说明                                                            |
| ---------- | --------------------------------------------------------------- |
| `page`     | 从 1 开始，默认 1                                               |
| `pageSize` | 默认 20，最大 100                                               |
| `sort`     | `字段:asc` 或 `字段:desc`，多个用逗号分隔；可排序字段由接口声明 |
| 筛选       | 由接口的 query schema 定义；关键字统一用 `keyword`              |

分页响应：`{ items, total, page, pageSize }`。

列表中的每一行带 `allowedActions`（如 `["update", "delete"]`），表示当前身份对这一行能做的操作。因为不同动作的数据范围可能不同（spec 05），前端按行显示按钮，不能只看全局权限码。

## 2. 错误码

5 位数字，前两位为模块段：

| 段    | 模块                                  |
| ----- | ------------------------------------- |
| 10xxx | 认证（spec 01）                       |
| 11xxx | 身份与权限（spec 02、04、05）         |
| 12xxx | 组织与部门（spec 03）                 |
| 13xxx | 学校服务（spec 07）                   |
| 20xxx | 学年与学校基础数据（spec 08、09、10） |
| 30xxx | 通用能力（spec 11）                   |
| 90xxx | 系统错误                              |

通用错误码：

| 码    | HTTP | 含义                                       |
| ----- | ---- | ------------------------------------------ |
| 90001 | 400  | 参数校验失败，`data.fields` 给出字段级错误 |
| 90002 | 409  | 数据已被他人修改（版本冲突），请刷新       |
| 90003 | 409  | 重复提交（幂等键已处理），返回首次结果     |
| 90004 | 404  | 数据不存在或无权查看                       |
| 90005 | 429  | 请求过于频繁                               |
| 90500 | 500  | 系统错误                                   |

> 无权查看的数据一律返回 404，不返回 403，避免泄露数据是否存在。没有某功能权限时返回 403。资源查询与鉴权代码用 `ApiException(90004)` 表示不可见资源。

错误码表在 `packages/contracts/src/errors.ts` 维护，前端据此展示文案。

## 3. 编码与 ID

| 类别     | 例子                                     | 生成                | 前端可输入 | 前端显示         |
| -------- | ---------------------------------------- | ------------------- | ---------- | ---------------- |
| 技术 ID  | 主键、schema 名                          | 系统，UUID v7       | 否         | 否               |
| 系统编码 | 角色、部门、权限、功能模块、应用、字典值 | 系统或代码声明      | 否         | 否，显示名称     |
| 系统编号 | 开通申请号、任务编号、待办编号           | 编号规则（spec 11） | 否         | 是               |
| 业务编号 | 学号、学校标识码、合同编号、证件号       | 现实世界            | 是         | 是（证件号脱敏） |

- 研发身份可在详情页“更多 → 复制技术 ID”，其他身份不可见。
- 接口路由可以带技术 ID，但界面不展示。

## 4. 公共字段

所有业务表（日志、关联表除外）都有：

| 字段                        | 说明                       |
| --------------------------- | -------------------------- |
| `id`                        | uuid，UUID v7，应用生成    |
| `created_at` / `updated_at` | timestamptz                |
| `created_by` / `updated_by` | 操作身份 id                |
| `deleted_at`                | 软删除时间，非空即在回收站 |
| `version`                   | int，乐观锁                |

## 5. 并发与幂等

- **乐观锁**：更新、删除请求必须带 `version`；与库中不一致返回 `90002`。
- **幂等**：新增、导入、开通、审批等提交接口要求请求头 `Idempotency-Key`（前端每次打开表单生成一个 UUID）。服务端在 Redis 保存 24 小时，重复请求返回首次结果。
- 前端提交中按钮禁用。

JSON 写接口通过 `Idempotent(operation, resolveScope)` 启用幂等。operation 使用稳定且唯一的业务操作名。resolveScope 依据服务端已验证的身份及租户上下文生成范围，访问权限由 Guard 在重放前检查。键按范围、HTTP 方法和操作名隔离。相同范围与操作的同键提交会沿用第一次提交，修改表单重新提交时使用新键。

Redis 原子占位与成功结果均保留 24 小时。正在处理或结果未知时，`409 / 90003` 的 data 为 `{ pending: true }`。成功后同键的 `409 / 90003` 将首次业务结果放入 data，并返回本次请求的 traceId。Redis 不可用时返回 503。占位后发生异常时保留占位，以免已发生的副作用被重复执行。Redis 数据丢失、过期或被驱逐后，保护随之结束。

## 6. 时间

- 存储一律 `timestamptz`；接口传 ISO 8601 字符串。
- 日期类业务（学年、学期、服务到期日）按 `Asia/Shanghai` 计算与显示，传 `YYYY-MM-DD`。

## 7. 软删除

- 删除操作设置 `deleted_at`，默认查询排除已删除数据。
- 回收站保留 30 天，可恢复；到期由任务彻底删除。
- 唯一约束使用部分索引 `WHERE deleted_at IS NULL`。

## 8. 版本

- 不兼容改动发布 `/api/v2`，与 v1 并存至少一个版本周期。
- 前端构建产物带版本号；服务端在响应头 `X-App-Version` 返回当前版本，前端发现不一致时提示“系统已更新，请刷新”。

## 9. 验收标准

- 任一接口传错参数返回 `90001` 并带字段级错误。
- 两人先后保存同一条记录，后保存者收到 `90002`。
- 同一 `Idempotency-Key` 提交两次，只产生一条数据。
- 界面任何位置不出现 UUID 和系统编码。
