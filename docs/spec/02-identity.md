# 02 · 身份与选择组织

## 1. 目标

一个账号拥有多个身份；登录后选择组织（身份）进入系统；工作中可随时切换。

## 2. 数据

**identities**

| 字段          | 说明                                                                                 |
| ------------- | ------------------------------------------------------------------------------------ |
| user_id       | 账号                                                                                 |
| type          | `company` · `bureau` · `agent` · `school` · `teacher` · `student` · `parent`（预留） |
| org_id        | 所属组织；teacher、student、parent 指向学校                                          |
| department_id | 所属部门，可空                                                                       |
| ref_id        | student 指向学校库学生 id；parent 预留                                               |
| title         | 职务，可空                                                                           |
| status        | 1 启用 · 0 停用                                                                      |
| sort          | 选择组织页的排序                                                                     |

约束：

- 唯一 `(user_id, org_id, type)`（未删除）。
- 身份类型与组织类型匹配：company↔company，bureau↔bureau，agent↔agent，school / teacher / student / parent ↔ school。
- M1 后台不允许 student、parent 身份登录后台（`client=admin` 时过滤）。

**identity_roles**：`(identity_id, role_id)`。

## 3. 身份上下文

每个请求加载并放入 CLS：

```ts
interface IdentityContext {
  userId: string;
  identityId: string;
  tokenVersion: number;
  client: "admin" | "mobile";
  identityType: IdentityType;
  orgId: string;
  orgType: OrgType;
  departmentId: string | null;
  roleIds: string[];
  // 权限码 → 该权限可用的数据范围。同一权限码由多个角色授予时，取这些角色中最宽的范围：
  // all > dept_and_below > dept > personal
  permissions: Map<string, DataScopeOption>;
}
```

> 不按“身份整体取最宽范围”，避免角色 A（本机构全部 + 只读）与角色 B（本部门 + 编辑）组合后变成“本机构全部 + 编辑”。

- 缓存于 Redis `ctx:{identityId}`，TTL 10 分钟。
- 以下变化时删除缓存：身份、角色、角色档位、部门调整、内置角色同步与模板修改、账号停用。多实例通过 Redis 发布订阅广播。

## 4. 接口

| 方法 | 路径                    | 令牌           | 说明                                               |
| ---- | ----------------------- | -------------- | -------------------------------------------------- |
| GET  | `/auth/identities`      | 账号级或身份级 | 我的身份列表（见下）                               |
| POST | `/auth/select-identity` | 账号级或身份级 | `{ identityId }` → 身份级令牌 + `me`               |
| GET  | `/auth/me`              | 身份级         | 当前用户、当前身份、权限码、数据范围摘要、可用模块 |

身份列表项：

```json
{
  "id": "…",
  "type": "agent",
  "typeName": "代理商",
  "orgName": "某体育服务代理商",
  "departmentName": "运营一部",
  "lastUsed": true,
  "available": true,
  "unavailableReason": null
}
```

`available=false` 的情况：组织停用、学校服务已停用（只允许学校管理员进入导出）、M1 中的 student / parent 身份。

## 5. 规则

1. 登录后：身份数量为 1 且可用 → 自动选择并进入选择模块页（唯一可用模块时直接进入工作台）；否则进入选择组织页。
2. 选择组织页按组织类型分组：公司 → 教育局 → 代理商 → 学校；`lastUsed` 的排在最前并显示“上次使用”标签；卡片初始不显示蓝色描边，仅在鼠标悬停或键盘聚焦时显示蓝色描边与箭头。
3. 选择身份时校验身份属于本人、状态启用、组织启用；写 `users.last_identity_id` 与审计 `identity.select`。
4. 切换身份（顶栏）与选择身份是同一接口；前端切换后清空所有缓存数据，回到新身份的选择模块页，并清空旧页签。
5. 一个会话同时只有一个身份。多个标签页共用同一个会话（refresh Cookie 是共享的），以最后一次选择为准：AuthGuard 校验令牌中的 `iid` 与会话当前的 `identity_id`（随会话缓存在 Redis）一致，不一致返回 401 与错误码 11005；前端收到 11005 后提示“已在其他页面切换身份”，清空缓存数据并跳到当前身份的选择模块页。

## 6. 错误码

| 码    | 含义                         |
| ----- | ---------------------------- |
| 11001 | 身份不存在或不属于当前账号   |
| 11002 | 身份已停用                   |
| 11003 | 组织已停用                   |
| 11004 | 该身份暂不支持登录后台       |
| 11005 | 已在其他页面切换身份，请刷新 |

## 7. 验收标准

- 只有一个身份的账号登录后直接进入选择模块页（唯一可用模块时直接进入工作台）。
- 多身份账号登录后看到按类型分组的组织卡片，上次使用的排第一。
- 切换身份后，原身份的列表数据不会在新身份下闪现。
- 修改某身份的角色后 5 秒内，该身份的菜单与接口权限生效。

## 8. 成员与身份管理接口（T-048）

成员列表的一行对应一个组织身份，`id` 为身份 id；账号凭证与各组织身份分开管理。以下接口要求身份级令牌：

| 方法  | 路径                  | 权限                | 说明                                                                                        |
| ----- | --------------------- | ------------------- | ------------------------------------------------------------------------------------------- |
| GET   | `/members`            | `org:member:view`   | 分页列表，支持姓名/登录账号关键字、部门（可含下级）、未分配、身份类型、身份状态和声明的排序 |
| GET   | `/members/:id`        | `org:member:view`   | 本组织身份详情及该账号其他组织身份的只读名称摘要                                            |
| POST  | `/members`            | `org:member:create` | 新建账号或明确追加已有账号的组织身份，支持幂等                                              |
| PATCH | `/members/:id`        | `org:member:update` | 带身份版本调整部门、职务及角色集合                                                          |
| POST  | `/members/:id/status` | `org:member:update` | 带身份版本启用或停用组织身份                                                                |

- `orgId` 只能放在 query：默认当前组织。真实持有平台内置超级管理员角色的公司身份可以指定组织；普通身份不能通过参数切换组织，访问其他组织身份返回 404。上级教育局管理员只能通过新增接口为下级教育局开通首个管理员，按区划路径验证严格上下级关系，目标已有可用管理员时拒绝此例外。部门、角色管理不因此扩大普通身份的组织边界。
- 新建请求的 `account` 显式分为 `mode=new`（用户名、姓名，可选手机号和邮箱）与 `mode=existing`（精确的用户名、手机号或邮箱）。不提供跨组织账号搜索接口。新建遇到已有凭证返回 `12008`；追加时不修改原账号姓名、密码、手机号、邮箱和启停状态；同组织同类型身份重复返回 `12009`。
- 新增的身份类型由目标组织决定。学校的教师身份创建及教师档案关联留在 T-095；本接口可以查询并调整已存在教师身份的部门与适用角色，不创建学生或家长身份。
- 新账号遵循 spec 01 初始密码策略并强制首次改密，创建结果返回初始密码；查询和后续修改均不返回密码。手机号加密并保存 HMAC，列表与详情仅返回脱敏值。幂等结果按 spec 00 返回首次创建结果；密码不进入审计或应用日志。
- 部门必须属于目标组织且未删除；角色必须启用、适用该身份，且为内置角色或本组织自定义角色。每个分配角色的最终授权与数据范围均不能超过操作人；不能修改自己的角色。对高于自己的成员不能调整部门、角色或启停，行 `allowedActions` 与服务端写校验保持一致。
- 停用仅修改当前组织身份，不停用全局账号，也不影响其他组织身份；停用身份关联的现有会话在下次鉴权时拒绝。角色和部门调整立即使身份上下文缓存失效。
- 写操作先取 T-045 权限写锁，再锁组织、账号/身份等业务行；部门分配与部门删除共用组织锁，避免分配到已删除部门。权限在取锁后重读，角色替换与停用调用管理员保留检查；版本、绑定和审计在同一事务提交。审计记录 `member.create`、`member.update`、`member.status`，不记录凭证明文。
