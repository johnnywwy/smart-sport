# 03 · 组织、学校档案、区划与部门

## 1. 目标

维护四类组织、行政区划、学校档案，以及每个组织自建的部门树和部门负责范围。

## 2. 数据

**regions**：`code`（国标区划码，主键）、`name`、`level`（1 省 · 2 市 · 3 区县）、`parent_code`、`path`（如 `330000.330100.330106`）、`status`。

**orgs**

| 字段        | 说明                                                   |
| ----------- | ------------------------------------------------------ |
| type        | `company` · `bureau` · `agent` · `school`              |
| name        |                                                        |
| code        | 系统生成，不显示                                       |
| region_code | 教育局为管辖区划；学校为所在区划；代理商为注册地，可空 |
| status      | 1 启用 · 0 停用                                        |

**school_profiles**

| 字段                                   | 说明                                                                          |
| -------------------------------------- | ----------------------------------------------------------------------------- |
| school_id                              | 主键                                                                          |
| school_code                            | 教育部学校标识码（10 位），唯一                                               |
| stages                                 | smallint[]，1 小学 · 2 初中 · 3 高中 · 4 大学                                 |
| stage_years                            | jsonb，如 `{"1":6,"2":3,"3":3,"4":4}`；小学 5/6，初中 3/4，高中 3，大学 3/4/5 |
| nature                                 | 公办 · 民办                                                                   |
| address / contact_name / contact_phone |                                                                               |

**departments**

| 字段      | 说明                                                                |
| --------- | ------------------------------------------------------------------- |
| org_id    |                                                                     |
| parent_id | 树形，根部门 parent 为空                                            |
| path      | 祖先 id 路径，用于“本部门及以下”                                    |
| name      | 同一上级下唯一                                                      |
| code      | 系统生成                                                            |
| sort      |                                                                     |
| is_preset | 公司预置部门（研发部、销售部、生产部、技术服务部）为 true，不可删除 |

**department_scopes**：`(department_id, scope_type, scope_value)`。

| 组织类型 | 允许的 scope_type   | scope_value                |
| -------- | ------------------- | -------------------------- |
| company  | `school` · `region` | 学校 id · 区划码           |
| bureau   | `region` · `school` | 辖区内的区划码 · 学校 id   |
| agent    | `school`            | 已授权学校 id              |
| school   | `grade` · `college` | 年级编码（如 13）· 学院 id |

## 3. 接口

| 方法        | 路径                                                         | 权限                             | 说明                                          |
| ----------- | ------------------------------------------------------------ | -------------------------------- | --------------------------------------------- |
| GET         | `/regions?parent=`                                           | 登录                             | 区划树按级加载                                |
| GET         | `/orgs?type&keyword&regionCode&page`                         | `platform:org:view`              | 组织列表（公司用）                            |
| POST        | `/orgs`                                                      | `platform:org:create`            | 新建教育局、代理商；学校走开通向导（spec 14） |
| PATCH       | `/orgs/:id`                                                  | `platform:org:update`            |                                               |
| POST        | `/orgs/:id/toggle`                                           | `platform:org:update`            | 启用 / 停用                                   |
| GET / PATCH | `/schools/:schoolId/profile`                                 | `school:profile:view` / `update` | 学校档案                                      |
| GET         | `/departments/tree`                                          | `org:department:view`            | 当前组织的部门树，含人数、负责范围摘要        |
| POST        | `/departments`                                               | `org:department:create`          | `{ parentId?, name }`                         |
| PATCH       | `/departments/:id`                                           | `org:department:update`          | 改名、调整上级（拖动）、排序                  |
| DELETE      | `/departments/:id`                                           | `org:department:delete`          | 有成员或子部门时拒绝                          |
| GET         | `/departments/:id/scopes`                                    | `org:department:view`            |                                               |
| PUT         | `/departments/:id/scopes`                                    | `org:department:update`          | 整体替换；返回合计可见数量                    |
| GET         | `/scope-options?type=school\|region\|grade\|college&keyword` | `org:department:update`          | 范围选择器可选项（只返回外边界内的）          |

## 4. 规则

1. 部门只属于本组织；接口按当前身份的 `org_id` 过滤，不接受外部传入的组织 id（公司超管除外，可指定 `orgId`）。
2. 调整上级时禁止形成环；更新自身及所有子孙的 `path`。
3. 部门负责范围只能选外边界内的值；代理商部门的学校在授权撤销后自动失效（计算时过滤，不删除记录，授权恢复后自动恢复）。
4. 区划按 `path` 前缀匹配：选择“浙江省”即包含其下所有市、区县及其学校，新开通的学校自动纳入。
5. 教育局的组织区划决定其辖区；教育局的部门只能选辖区内的区划或学校。
6. 部门、负责范围变化后，删除受影响身份的上下文缓存与可见范围缓存。

## 5. 错误码

| 码    | 含义                             |
| ----- | -------------------------------- |
| 12001 | 部门名称在同级已存在             |
| 12002 | 部门下还有成员或子部门，不能删除 |
| 12003 | 不能把部门移到自己的下级         |
| 12004 | 负责范围超出本组织可见范围       |
| 12005 | 学校标识码已存在                 |
| 12006 | 学段与年限配置不合法             |
| 12007 | 预置部门不可删除                 |

## 6. 验收标准

- 代理商管理员只能看到本代理商的部门；部门负责范围的学校候选只有授权学校。
- 把“浙江销售组”的范围设为浙江省后，浙江新开通的学校无需操作即可被该组成员看到。
- 拖动部门到另一个上级后，“本部门及以下”的结果随之变化。

### 学校档案接口契约（T-032）

- 学校档案位于 `public.school_profiles`，不是学校业务 schema；创建由后续开通流程复用内部服务，GET 不隐式创建，不新增公开创建学校接口。
- 标识码为10位数字字符串，保留前导零，未删除档案之间唯一。学段非空、不重复，各学段年限必须与所选学段一一对应，只允许表中列出的年限。
- PATCH 提交 `version、schoolCode、stages、stageYears、nature、address、contactName`，其中 `nature` 为“公办”或“民办”，地址和联系人可为空。`contactPhone` 可省略（保留原号码）、传新号码或 `null`（清空）；支持手机号和固定电话。响应只含脱敏号码，不返回密文或哈希，也不提供全文查看入口。
- 响应另含 `schoolId、schoolName、version、allowedActions`；学校名称来自组织，不能通过档案修改。`allowedActions` 按修改权限自己的学校范围计算。格式错误返回90001，学段与年限不对应返回12006，标识码重复返回12005。
- 当前范围基础支持公司按动作访问其真实可见学校；学校/教师身份仅在本校且该动作范围为 `all` 时开放整校档案。代理商授权上限、学校/教师的年级与学院细分范围尚待 T-052/T-053/T-054，未就绪分支拒绝访问，不当作全范围。档案控制器标注 `@SchoolScoped()`，局部守卫在幂等重放前校验学校，Service 在权限版本屏障锁内重新校验；完整学校库服务状态守卫仍归 T-053。
- 创建由内部 `SchoolProfilesService.initialize` 接受调用者的数据库事务，失败与开通事务一起回滚。公司读取、所有档案修改写学校级审计，联系电话只记“已修改”；档案变化推进身份/范围缓存版本，为后续学制及学校类型计算失效旧快照。

### 部门树交互补充

部门支持逐层创建，不设业务层级上限；拖动可调整上级，仍须防止形成环。树底“新建部门”和行内“+”打开同一表单：部门名称、树形上级选择（默认当前部门）、完整位置预览。负责范围计算仍遵守 spec 05，不因设计稿示例文案引入自动继承。

### 部门树接口契约（T-033）

- 查询返回 `{ items, unassignedMemberCount, allowedActions }`（T-162 补充顶层 `create` 能力，空树也能正确控制新建入口；不依赖角色管理权限），节点包含 `id、parentId、name、sort、isPreset、version、memberCount、scopeSummary、allowedActions、children`。人数统计未删除身份对应的直属去重账号，包含停用成员；未分配部门按同样口径单独统计。范围摘要按类型返回实际配置条数，不等于可见学校计算结果（T-034/T-051）。
- 新建只接收 `{ name, parentId? }`；修改接收 `{ version, name?, parentId?, sort? }`，至少修改一项，`parentId: null` 表示根部门；删除 body 为 `{ version }`。系统编码、路径、组织归属、预置标记均不能由客户端写入。
- 四个接口均可通过 query `orgId` 指定目标组织，但只有真实绑定平台内置超级管理员角色的公司身份允许使用；普通身份传入组织参数返回 403，访问其他组织的部门返回 404。
- 移动时同步递增所有子孙的版本，旧版本编辑返回 90002。路径包含自身，形式为 `根ID.上级ID.自身ID`，不设业务层级上限。
- 公司预置部门通过幂等初始化服务创建，服务启动时为现有公司补齐；未来 T-140 的公司初始化流程复用该服务。GET 不隐式建部门，重复初始化不覆盖改名、移动、排序。

### 部门负责范围契约（T-034）

- 与 T-050/T-051 的已确认阶段保持一致：当前 company、bureau 开放学校和区划，其他组织暂只允许空数组清空，非空配置或未开放的选项类型返回 422 / 12004。代理商授权、学校年级及学院数据就绪后再补齐，不返回未经校验的候选。
- `PUT /departments/:id/scopes` 接收 `{ version, scopes: [{ type, value }] }`，整体替换；使用部门版本，与改名、移动和删除共用乐观锁，成功递增一次。需要 `Idempotency-Key`，记录 `department.scopes.update` 审计，失败不修改版本、范围或审计。
- GET、PUT 均返回 `{ departmentId, version, scopes, schoolCount, allowedTypes, allowedActions }`。每项范围包含 `type、value、name、available、parentValue`，名称由服务端获取；已停用、删除或超出当前外边界的已保存范围保留值，但使用通用的失效名称。`schoolCount` 是当前部门配置展开后的启用学校去重数，不包含下级部门、角色或成员的额外负责，也不等于成员最终实际可见数。
- `/scope-options` 接收 `type、keyword?、parent?、page、pageSize、orgId?`，分页返回 `{ items, total, page, pageSize, allowedTypes }`，项目结构同上述范围。`parent` 仅区划可用；不传上级及关键字时，公司从省级开始、教育局从本级辖区开始；传上级逐级加载，关键字可在边界内搜索。学校仅返回启用、未删除且所在区划启用的候选。
- 三个接口均遵守部门组织隔离和真实平台超管的 `orgId` 约定。教育局候选与写入只允许本级及后代；不可见部门、范围值或上级区划返回 404 / 90004，缺功能权限返回 403 / 11101。部门管理限本组织，不以操作人的学校业务数据档位替代组织边界。

### 行政区划管理接口（T-164，2026-11-18 确认）

- 原 `/regions?parent=` 登录查询契约保持不变，继续用于各业务的区划选择器。
- 新增公司专用 `/region-management`（GET，`system:region:view`），按上级、名称和分页查询有效区划。返回上级名称、本级及后代未删除学校数、直接关联的全部未删除教育局（包含停用状态）；停用或未开通服务的学校仍计数。行能力为查看，界面不显示技术编码。
- `/region-management/sync-preview`（GET）与 `/region-management/sync`（POST）均要求公司 `system:region:import`。预览使用随项目发布、固定来源提交与 SHA-256 的审核文件，显示数据版本、审核日期、新增、改名、撤销、改隶与受影响组织/部门范围/本人范围。此处审核是项目数据审查，不新增多人审批流程，也不运行在线抓取。
- 确认仅提交预览 fingerprint，并使用 Idempotency-Key。指纹绑定审核文件、全量现有区划及关联数据；变化返回90002，必须重新预览。确认事务串行化区划导入、锁定权限及关联数据后重查授权、影响和指纹，更新与审计共同提交。
- 新增和同码改名可同步；撤销/改隶若涉及组织归属、上下级区域范围或教育局外边界，整批禁止执行，先人工处理关联并重新预览，不部分提交。停用旧区划但不物理删除，不自动迁移学校/教育局归属，也不修改已保存范围。没有影响的变更可以同步，应用后失效区划及范围缓存。
- 审核文件与现有目录完全相同时，显示无变更并禁止提交。学校/教育局计数及关联均来自数据库，不生成设计稿示例数。
