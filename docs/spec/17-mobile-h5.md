# 17 · 移动端 H5（M2）

> 本文档是 M2 的设计规格。M1 不实现移动端，`TASKS.md` 暂不排移动端任务；这里先把页面、导航、身份规则、数据设计和组件定下来，供设计评审和后续拆任务。第 9 节列出 M1 现在就要遵守的约束，避免以后返工。
>
> 设计稿：`docs/智慧体育云后台设计稿.html` 第四行 M01–M07。视觉风格仍在评审（浅色卡片布局方向），定稿前以本文的内容和规则为准，配色和样式不作为验收依据。

## 1. 目标与范围

给学生、教师、家长用的手机网页。在微信里点链接或公众号菜单打开，也可以用手机浏览器打开，不需要安装 App。

- 包含：登录、选择身份、家长绑定孩子、各身份的首页、班级与学生（教师）、成绩查看、消息、我的（改密码、切换身份、退出）。
- 运动业务（跳绳、跑步、体测录入等）只定页面结构和入口位置，具体功能随各运动业务的规格另写。
- 不包含：后台管理功能（公司、教育局、代理商、学校管理员身份在 H5 里不能进入，提示用电脑登录后台）、原生 App、微信小程序、微信分享卡片、横屏布局。

## 2. 技术选型

| 项     | 选择                                                | 说明                                                                                                                       |
| ------ | --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 应用   | `apps/h5`，独立的 Vite 应用                         | 与 `apps/web` 同一个 monorepo，单独构建；部署为同域名下的 `/h5/` 路径，与后台共用 `/api`；会话独立，见第 9 节第 5 条       |
| 组件库 | HeroUI 3（网页版，开源部分）                        | 与后台一致。不用 HeroUI Native：它是 React Native 组件库，不能在浏览器和微信里运行。H5 不依赖 HeroUI Pro                   |
| 复用   | `packages/contracts`、`packages/domain`、接口客户端 | 类型、校验、年级计算全部复用。M2 开工时把 `apps/web/src/shared/api` 里与页面无关的部分提到 `packages/api-client`，两端共用 |
| 其余   | 与后台相同                                          | React 19、Tailwind CSS 4、React Router 7、TanStack Query 5、zustand 5                                                      |
| 菜单   | `menus.client = mobile`                             | 菜单仍由 contracts 声明并同步，见 spec 04；H5 读取 `GET /menus/current?client=mobile`                                      |
| 浏览器 | 复用 T-152 的能力探测                               | 微信内置浏览器按能力放行，不按 UA 拦截                                                                                     |

HeroUI 3 没有专门的手机导航组件，下面几个在 `apps/h5` 的基础组件层自己实现（四层组件规则见 spec 16）：

| 组件                 | 用途                                 | 实现                                 |
| -------------------- | ------------------------------------ | ------------------------------------ |
| `TabBar`             | 底部标签栏，3 到 4 项                | 自建；固定在底部，带安全区内边距     |
| `NavBar`             | 顶部导航栏：返回、标题、右侧操作     | 自建                                 |
| `Cell` / `CellGroup` | 设置项、信息行（左标题、右值、箭头） | 自建，基于 HeroUI 的列表或按钮       |
| `PullRefresh`        | 下拉刷新                             | 自建                                 |
| `InfiniteList`       | 滚到底自动加载下一页，每页 20 条     | 自建，基于 TanStack Query 的分页查询 |
| `ActionSheet`        | 底部弹出的选择面板                   | 基于 HeroUI 3 的弹层组件，从底部弹出 |

按钮、输入框、卡片、标签、头像、分段切换、开关、提示、骨架屏、加载圈直接用 HeroUI 3 的组件。具体组件名和写法以安装版本的文档为准。`scripts/check-ui.mjs` 的控件检查同样覆盖 `apps/h5`。

## 3. 登录与身份

### 3.1 登录

登录页有两个页签：

| 页签       | 谁用       | 填写                            |
| ---------- | ---------- | ------------------------------- |
| 手机号登录 | 教师、家长 | 手机号或用户名 + 密码           |
| 学生登录   | 学生       | 学校（可搜索选择）+ 学号 + 密码 |

- 学生账号的用户名由系统生成，学生不需要记，用学校加学号登录。学号只在本校唯一，所以必须先选学校。查找方式见 3.4 的 `student_logins`。
- 学校搜索接口不需要登录，只返回已开通且服务未停用的学校名称和所在区县，按关键字搜索，不提供全量列表，按 IP 限流。
- 学生初始密码：开发和测试环境统一为 `123456`；生产环境由学校在后台批量生成随机初始密码并导出发放，首次登录必须修改。
- 登录失败的提示与后台一致，不区分“账号不存在”和“密码错误”（spec 01）。学生登录的失败计数按“学校 + 学号”记，Redis 键 `login:fail:stu:{schoolId}:{学号}`。
- 令牌与后台相同的两阶段方式，`client=mobile`：先拿账号级令牌，选择身份后拿身份级令牌（spec 01、02）。access token 只放内存。

### 3.2 选择身份

- 只列出 `teacher`、`student`、`parent` 三类身份。账号还有其他身份时，在列表下方提示“其他身份请用电脑登录后台”，不列出来。
- 只有一个可用身份时跳过这一页，直接进入。
- 一个人可以同时是教师和家长（如本校老师的孩子也在本校）。进入后在“我的 → 切换身份”里切换，切换时清空全部缓存（AGENTS 规则 24）。
- 反过来，后台（`client=admin`）继续过滤 `student`、`parent` 身份（spec 02）。

### 3.3 家长绑定孩子

家长身份通过绑定孩子产生，不由学校创建。

1. 学生在 H5 “我的 → 家长绑定码”里看到一个 6 位绑定码，7 天有效，可以刷新（刷新后旧码作废）。
2. 家长用手机号登录（还没有账号的先用手机号注册并设置密码），进入“绑定孩子”，选学校、填学号、孩子姓名、绑定码，再选自己和孩子的关系（父亲、母亲、其他）。
3. 校验通过后，为家长账号创建一个该校的 `parent` 身份，关联到这个学生；已有该校的 `parent` 身份就只追加孩子。
4. 一个孩子最多绑定 4 位家长。学校管理员可以在后台学生详情里看到并解绑家长。
5. 一个家长可以绑定多个孩子（可以在不同学校）。首页顶部切换孩子；孩子在不同学校时，切换孩子就是切换 `parent` 身份。
6. 绑定、解绑写审计日志。学号加姓名加绑定码连续错 5 次，锁定该学号的绑定 30 分钟。
7. 孩子转学后，绑定关系跟着学生索引走：原校的 `parent` 身份不再显示这个孩子，新校自动生成 `parent` 身份并关联，不需要重新绑定。孩子毕业离开平台后，绑定保留只读，可以看历史成绩。

数据范围：`student` 固定只看自己，`parent` 固定只看已绑定的孩子（spec 04、05）。

### 3.4 数据设计（M2 新增）

都在 `public`，因为登录和绑定发生在选择身份之前，不能依赖学校库。

| 表               | 字段                                                                                                | 约束                                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `student_logins` | school_id、student_no、user_id、student_index_id                                                    | `(school_id, student_no)` 唯一（未删除）；学号修改、转学时同数据源同事务更新，跨数据源通过outbox同步    |
| `guardian_links` | user_id（家长账号）、student_index_id、relation（father · mother · other）、verified_at、revoked_at | 架构图已预留的表名和字段；同一学生未解除的记录不超过 4 条；`(user_id, student_index_id)` 唯一（未删除） |
| `bind_codes`     | student_index_id、code_hash、expires_at、revoked_at                                                 | 每个学生只有一条有效码；只存哈希                                                                        |

- `parent` 身份的 `ref_id` 留空，孩子列表从 `guardian_links` 计算，按孩子当前所在学校分到对应的 `parent` 身份。
- 学生账号在学校开通“学生登录”后由学校批量生成，写 `users`、`identities(type=student)`、`student_logins`，并回填 `student_index.user_id`（spec 10）。
- 错误码在 M2 拆任务时登记到 spec 00，预留号段 `30xxx`。

## 4. 导航与布局

- 一级页面：顶部标题 + 内容 + 底部标签栏。
- 二级页面（详情、表单）：整屏推入，顶部导航栏带返回，没有底部标签栏。手机的返回键和左滑返回都退回上一页。
- 选择类操作用底部弹出面板；需要确认的操作用居中对话框；结果用顶部短暂提示。
- 底部标签栏按身份不同：

| 身份 | 标签 1 | 标签 2 | 标签 3 | 标签 4 |
| ---- | ------ | ------ | ------ | ------ |
| 学生 | 首页   | 运动   | 成绩   | 我的   |
| 教师 | 首页   | 班级   | 布置   | 我的   |
| 家长 | 首页   | 成绩   | 消息   | 我的   |

标签项由 `client=mobile` 的菜单决定；某个应用学校没有开通时，对应标签不显示（spec 07）。

## 6. 交互与适配规则

1. 按设计宽度 390 px 出图；在 320 px 到 480 px 宽度内不出现横向滚动。
2. 可点区域不小于 44 × 44 px。正文字号不小于 14 px；输入框字号 16 px，避免 iOS 聚焦时页面被放大。
3. 顶部、底部留出安全区（`env(safe-area-inset-*)`），底部标签栏不被手势条遮挡。
4. 列表页支持下拉刷新；长列表滚到底自动加载下一页，每页 20 条，没有更多时显示“没有更多了”。
5. 加载时先显示骨架屏；请求失败显示错误提示和“重试”；断网时顶部显示“网络已断开”。
6. 身份标签颜色：教师青（与后台一致）、学生蓝、家长粉；只用在身份卡片和“我的”页的身份标签上。
7. 学生和家长看到的页面里不出现其他学生的证件号、手机号，也不出现其他学生的成绩排名。
8. 微信内置浏览器和 iOS Safari、Android Chrome 的最近两个大版本都要能正常使用。

## 8. 验收标准

- 学生用“学校 + 学号 + 密码”能登录并进入学生首页；生产环境不能用 `123456` 作为密码。
- 同时有教师和家长身份的账号，登录后先选身份，进入后可以在“我的”里切换，切换后看不到上一个身份的数据。
- 只有学校管理员身份的账号登录 H5，看到“请用电脑登录后台”的提示，不能进入。
- 家长用正确的学号、姓名、绑定码能绑定孩子；绑定码错误 5 次后锁定 30 分钟；同一个孩子第 5 位家长绑定被拒绝。
- 孩子转学后，家长不用重新绑定，就能在新学校的身份下看到孩子。
- 教师的班级页只出现本人任教的行政班和教学班。
- 在 390 px 和 320 px 宽度下，所有页面没有横向滚动，底部标签栏不被手势条遮挡。

## 9. M1 现在就要遵守的约束

这些不需要在 M1 实现功能，但 M1 的代码不能把路堵死：

1. `users.username` 全局唯一，学生账号用系统生成的用户名，不要把学号直接当用户名。
2. 菜单声明保留 `client` 字段，后台只读 `client=admin`；不要把“菜单只有后台一种”写死在 contracts 或导航代码里。
3. 学校库的学生表变更学号时要能通知平台库（outbox 事件 `student.no_changed`），M2 用它同步 `student_logins`。
4. 学生转学、毕业的流程（spec 10）里，`student_index` 是跨校的唯一锚点，绑定、登录都挂在它上面，不挂学校库的学生 id。
5. 会话带 `client`（spec 01），后台和 H5 是两个独立会话。同一浏览器同时登录两端时 refresh Cookie 不能互相覆盖：Cookie 名按 client 区分（后台沿用现名，H5 另起一个），路径都是 `/api/v1/auth`。M1 的刷新、退出接口按请求声明的 client 读对应 Cookie，不要假设只有一个 Cookie 名。

实施边界：第9节第5条为双客户端会话约束，当前M1仅实现admin，尚无mobile刷新/退出请求契约。实施前须单独确认client选择及缺省/兼容行为并补共享契约与测试；本轮不直接修改认证接口。跨数据源登录映射同步期间不得使用旧学校映射获得身份，具体拒绝/重试行为在M2任务拆分时明确。
