# 13 · Web 后台

> 页面长什么样以设计稿为准（“智慧体育云后台设计稿”画布）。本文件写清路由、外壳、页面清单和流程，供前端实现。
> 其他文档里的“门户”一词，指本文件的“选择模块”页；“应用工作区”指“模块工作区”。

## 1. 页面流

```
/login ──> (/change-password) ──> /select-org（多身份时） ──> /modules（多模块时） ──> /m/:moduleCode/...
```

| 路由                       | 页面           | 说明                                                                                                                           |
| -------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `/login`                   | 登录           | 左侧图形，右侧账号 + 密码；失败 5 次出现图形验证码；“忘记密码”走邮箱验证码                                                     |
| `/change-password`         | 强制改密       | `mustChangePassword` 时进入，改完继续                                                                                          |
| `/select-org`              | 选择组织       | 按组织类型分组的身份卡片；上次使用的排第一；不可用的身份置灰并说明原因。只有一个身份时跳过                                     |
| `/modules`                 | 选择模块       | 一行 4 张模块卡片（图标、名称、一句说明、菜单预览）；数据来自 `GET /modules/available`。只有一个可用模块时跳过，直接进入该模块 |
| `/m/:moduleCode/*`         | 模块工作区     | 左侧是该模块的“分组 → 菜单”；路由由菜单生成                                                                                    |
| `/m/:moduleCode/workbench` | 工作台         | 每个模块侧栏的第一项，也是进入模块后默认打开的页面。指标卡、待办、最近访问（见第 2 节）                                        |
| `/403` `/404`              | 无权限、不存在 |                                                                                                                                |
| `/upgrade-browser`         | 浏览器版本过低 | 入口脚本检测，不满足基线直接跳转                                                                                               |

M1 的模块：`base` 基础信息、`platform-admin` 平台管理（仅公司）。分组与菜单的完整清单见 spec 04 第 3.1 节。

## 2. 工作台

工作台是每个模块侧栏的第一项（在分组之上，不属于任何分组），进入模块后默认打开。它登录即可用，不需要单独的权限；页签栏里的“工作台”页签不能关闭。各模块的工作台结构相同，指标卡按“当前身份 + 当前模块”取：基础信息模块见下表，平台管理模块显示开通与服务相关的指标，以后的运动模块各自声明。

- **指标卡**（按身份、按数据范围统计）：

| 身份    | 卡片                                                          |
| ------- | ------------------------------------------------------------- |
| company | 负责学校数；试用中 / 30 天内到期 / 宽限期学校；待审核开通申请 |
| bureau  | 辖区学校数；已开通平台学校数；按区县开通情况                  |
| agent   | 授权学校数与即将到期的授权；本部门负责学校                    |
| school  | 班级、学生、教师数；学年升级状态；待确认转学                  |
| teacher | 任教班级与学生数                                              |

- 指标卡显示当前值、与上周相比的变化、近 30 天迷你趋势；点击跳转到对应列表（已带好筛选）。接口 `GET /portal/kpis?module=` 一次返回当前身份在该模块的全部指标。
- 待办与最近访问：最近 5 条待办；最近打开过的 5 个页面（本地记录）。
- 外壳与模块内其他页面完全相同，左侧就是当前模块的菜单，“工作台”为选中状态。待办、任务、消息从顶栏进入，不占侧栏。

## 3. 模块工作区外壳

所有模块内页面共用一个外壳（`AppLayout`）。

| 区域     | 内容                                                                                                                                                                                                        |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 侧栏顶部 | 产品名“智慧体育云平台”                                                                                                                                                                                      |
| 侧栏中部 | 第一项固定是“工作台”；下面是当前模块的菜单：一级是小号灰色分组标题（不可点），二级是菜单项（图标 + 名称，可带数字角标）。数据来自 `GET /menus/current?module=`                                              |
| 侧栏底部 | 切换模块：显示当前模块名，点击弹出可用模块列表与“查看全部模块”                                                                                                                                              |
| 顶栏左   | 侧栏折叠按钮（左缘与主内容区左缘对齐）+ 面包屑“模块 / 菜单 / 子页面”                                                                                                                                        |
| 顶栏右   | 学年学期选择（默认当前学期）、待办铃铛、切换组织（下拉列出全部身份 +“查看全部组织”，选择后进入新身份的选择模块页）、头像菜单（个人资料、修改密码、登录设备、退出登录）                                      |
| 页签栏   | 顶栏下面单独一条白色圆角条，不放在主内容卡片里。第一个是“工作台”（不能关闭），后面是已打开的菜单，每个页签上有自己的关闭按钮（×）。关掉当前页签后切到剩下的最后一个；全部关掉后回到工作台。不提供“关闭其他” |
| 主内容区 | 页签栏下面的白色圆角卡片，放当前页面                                                                                                                                                                        |

- 侧栏有“展开”与“图标栏”两种模式，记住用户的选择；窄屏时变为抽屉。
- 身份标签颜色：公司蓝、教育局紫、代理商琥珀、学校绿、教师青；全站一致。
- 当前学校：公司和代理商身份可以看多所学校，进入学校内菜单时要先确定是哪一所。规则如下：
  - 位置：主内容卡片里，页面标题旁边的一个可搜索下拉（如“班级管理　西湖第一小学”）。不放在顶栏，不放在查询条件行；点“重置”不会清空它。
  - 出现的菜单：院系专业（仅大学）、班级管理、学生管理、教师管理、学年升级、转学管理、代理商授权。组织架构、成员账号、角色权限、操作记录显示的是自己组织的数据，不出现。
  - 出现的身份：只有 company 和 agent。bureau 看不到这些菜单；school、teacher 的学校固定，标题旁没有下拉。
  - 候选学校来自 `/scope/schools`：公司是全部学校，代理商是已授权且未到期的学校。下拉顶部列出最近进过的 5 所。
  - 还没选时：下拉显示“请选择学校”，标题下面提示先选学校并列出可选学校，不显示空表。
  - 选中后在上面这些菜单之间保持，换菜单不用重选；在下拉里可以直接换一所，当前菜单不变。切换组织或角色时清空。
  - “学校管理”的学校列表每行有“进入”，效果等于选中这所学校并打开班级管理。
  - 代理商选中学校后，没有被这所学校授权的菜单不显示。
  - 公司或代理商修改学校数据时，新增、编辑、删除等弹窗里加一句“你正在以某组织的身份修改某学校的数据，这次操作会记入该校的操作记录”。查看和导出不加。
  - “当前学校”只是前端的页面状态；调用接口时学校 id 仍然显式放在路径里（`/schools/:schoolId/...`），后端不依赖它。

列表页的统一结构：标题与一句说明 → 右上角操作按钮（导入、导出、新增）→ 查询条件 + “查询”“重置” → 表格 → 底部一行：最左是“共 N 条”，最右是每页条数和页码。按钮高度统一 36。

反馈：新增与编辑用弹窗；成功、失败、警告用右上角提示；删除、收回、撤销等不可轻易恢复的操作用确认框并说明后果。

页面上每个按钮都要走完“点击 → 弹窗 → 结果提示”，不能有点了没反应的按钮：

| 按钮类型                                               | 弹窗内容                                               | 确认后                   |
| ------------------------------------------------------ | ------------------------------------------------------ | ------------------------ |
| 新增、编辑                                             | 表单；不能改的字段只读显示并说明原因；底部一句规则说明 | 提示“已保存……”，列表刷新 |
| 查看、详情                                             | 只读信息，只有“关闭”                                   | 无                       |
| 删除、撤回、恢复默认                                   | 红色说明后果（能否恢复、影响谁），确认按钮为红色       | 提示结果和恢复办法       |
| 拒绝、收回、改系统参数                                 | 同上，另加必填的原因                                   | 提示结果                 |
| 导出                                                   | 导出范围、条数、是否含敏感信息                         | 提示条数，并记入操作记录 |
| 多步业务（导入、学年升级、转学、代理商授权、开通学校） | 不用弹窗，进入 5.2 的流程页                            | 见各流程                 |

## 4. 通用组件

| 组件             | 说明                                                                                                                                               |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<Can perm>`     | 按权限码显示子元素                                                                                                                                 |
| `DataTable`      | 搜索栏、筛选、分页、排序、列设置；按权限自动显示“新增、导入、导出、批量删除”；行操作“查看、编辑、删除”按该行的 `allowedActions` 显示；“回收站”页签 |
| `SchemaForm`     | 由 Zod schema 生成表单校验；提交自动带 `version` 与幂等键                                                                                          |
| `ImportWizard`   | 上传表格 → 核对数据 → 导入结果（见 5.2）                                                                                                           |
| `StepFlow`       | 多步流程的外框：步骤条、上一步 / 下一步、完成页。学校开通、学年升级、转学共用                                                                      |
| `ScopePicker`    | 按组织类型切换单位：区域树 / 学校搜索 / 年级格子 / 学院列表；右侧实时合计                                                                          |
| `MaskedField`    | 脱敏显示，有权限者点击查看                                                                                                                         |
| `VersionWatcher` | 发现新版本时提示刷新                                                                                                                               |
| `ErrorBoundary`  | 捕获渲染错误并上报（P1）                                                                                                                           |

所有界面不显示 UUID 与系统编码（spec 00）。

T-160 当前实施范围（2026-11-16）：公司、教育局先提供区域树与学校搜索，候选统一使用 `/scope-options` 的目标组织外边界，不以全量 `/regions` 代替。`ScopePicker` 通过 props 接收候选、已选项和回调，查询由独立 hook 完成；业务容器切换身份、组织或编辑对象时重置草稿。父级区域包含全部后代，已加载下级显示包含状态；先前显式选择的子级在取消父级后仍保留。搜索与分页不清除选择，失效项隐藏原名称、允许移除，只读不可修改。右侧先实时展示真实选择条目数，未保存草稿的学校去重数待 T-055 接入，不能显示示例数或沿用旧 `schoolCount`。代理商、年级与学院候选随对应后端依赖补齐，不视为全类型已完成。

## 5. 页面清单与流程

### 5.1 基础信息模块

| 分组     | 菜单       | 页面要点                                                                                                                                                                                                                                           |
| -------- | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 组织权限 | 组织架构   | 左侧部门树（人数、拖动调整上级、“未分配部门”常驻）；右侧“成员 / 负责范围”页签。部门可以逐层往下建，层数不限：树下方的“新建部门”和每个部门行上的“+”都打开同一个弹窗（部门名称、上级部门树形下拉，默认为当前选中的部门），弹窗里显示新部门的完整位置 |
| 组织权限 | 成员账号   | 账号列表（姓名、登录账号、部门、角色、状态）；右侧“分配角色”面板：所在部门、角色多选（每个角色一句说明）、保存后的效果预览、该账号在其他组织的身份（只读）。未分配部门或角色的账号醒目标出                                                         |
| 组织权限 | 角色权限   | 左侧角色列表（内置 / 自定义标签）与新建角色按钮；右侧数据范围卡片和菜单按钮权限树，改过的功能标“已改”；右栏实时预览菜单。影响人数及估算数据量待对应后端就绪后接入                                                                                  |
| 学校数据 | 学校管理   | 多校身份：可见范围内的学校列表，“进入学校”设为当前学校；学校身份：本校档案与平台服务状态                                                                                                                                                           |
| 学校数据 | 院系专业   | 仅大学显示。左边学院，右边该学院的专业；增删改都在本页。层级是学院 → 专业 → 行政班                                                                                                                                                                 |
| 学校数据 | 班级管理   | 行政班、教学班；导入。大学的行政班多一个“院系 / 专业”查询条件和一列，新增时必选院系和专业                                                                                                                                                          |
| 学校数据 | 学生管理   | 列表、新增弹窗、导入、导出；证件号与电话默认脱敏                                                                                                                                                                                                   |
| 学校数据 | 教师管理   | 教师资料与任课安排；导入                                                                                                                                                                                                                           |
| 学籍变动 | 学年升级   | 概览页 + 升级流程（5.2）                                                                                                                                                                                                                           |
| 学籍变动 | 转学管理   | 申请列表（方向、对方学校、状态）+ 转入流程（5.2）                                                                                                                                                                                                  |
| 授权记录 | 代理商授权 | 已授权列表 + 授权与收回流程（5.2）                                                                                                                                                                                                                 |
| 授权记录 | 操作记录   | 本组织的操作，只读，可导出                                                                                                                                                                                                                         |

P1：谁能访问本校数据（列出可访问本校的代理商与公司人员及其能做的事、最近 30 天访问记录）；“以 TA 的视角预览”。

学校档案前端第一阶段（T-167，2026-11-17）：沿用“学校管理”菜单，学校/教师身份展示本校档案，公司列表按 `ops:school:view` 和 `school:profile:view` 分别查询范围并控制入口，编辑按钮使用档案自己的 `allowedActions`。表单使用 T-032 更新契约；学校端的标识码、学段与学制按设计稿只读，公司端可编辑。学校名称、地区由组织信息维护，档案契约没有地区名称时不伪造地区显示。电话初始不填入脱敏值：保持空白保留原号码，输入新号码替换，显式“清空原号码”提交 null，可撤销清空。版本冲突保留草稿并提供重新加载。平台服务尚无查询契约，卡片明确显示待接入状态，后续服务功能就绪后再展示真实期限和开通模块。

### 成员列表与分配表单（T-171）

- 成员账号与组织架构的成员页签共用真实 `/members` 接口；部门页签默认查看直属成员，可切换包含下级。未分配部门或角色醒目标出。状态按服务端身份与账号状态展示，不推断首次登录状态。
- `GET /members/options` 使用 `org:member:view`，沿用 `/members` 的组织隔离与 `orgId` 约定。返回新增能力、本组织未删除部门的名称层级，以及当前人可授予的角色最终档位与范围；没有成员新增或修改权限时角色选项为空，不要求额外持有部门或角色管理权限。服务端写入仍重新检查行权限、角色上限、身份类型和版本。
- 角色多选仅显示适用目标身份的选项；自己的角色只读。效果预览依据最终角色与共享菜单声明，逐权限说明范围，不把最宽范围套到全部动作，不展示未实现的估算人数。
- 批量移部门或设置角色只处理本页仍可修改的勾选身份，逐条携带原版本提交。部分失败时显示成功数量及失败成员和原因，只重试尚未成功的记录；不自动改用新版本覆盖冲突。
- 新增表单明确区分新建账号与追加已有账号身份。初始密码只在成功结果中临时展示，不写入浏览器持久存储；关闭后清除。停用确认说明仅影响本组织身份，保存和启停遵守统一提示及冲突处理规则。

### 角色权限与角色模板的已确认交互补充

- 配置区和实时预览均使用 HeroUI Pro `FileTree`，按 contracts 的“模块 → 分组 → 菜单”声明展示，不自行创建菜单。分组右侧放展开箭头，隐藏引导线；保留灰色外框、圆角白色节点及行间分隔线。菜单旁直接显示动作复选框，不再显示四档切换和“细调”按钮；底层仍使用 spec 04 的档位契约提交。
- “班级管理”仅含行政班、教学班；“院系专业”独立，仅大学适用；“学校管理”不额外生成“学校档案”子菜单。
- “基础信息 → 角色权限”提供新建本组织角色：输入角色名称、选择内置基础角色，初始沿用其权限及数据范围，再编辑差异；可分配的动作和范围不能超过操作人。内置角色与当前身份自身角色只读，按钮同时遵守真实权限与 `allowedActions`。
- 保存和恢复都需确认；恢复使用红色说明和红色按钮。版本冲突保留草稿、禁用再次保存并允许重新加载；有未保存改动时，切换角色或新建需先确认放弃。平台“角色模板”不提供新增内置角色操作。
- 实时树预览反映草稿中的菜单与动作；实际登录后的可见数据仍受组织边界、学校类型、开通模块与授权限制。T-047/T-055 就绪前不展示模拟人数或数据量。

### 顶栏学年学期选择器实施约定（T-156）

- 各模块共用 HeroUI 学年学期选择器；按学年倒序分组，平台当前学期单独标记，选中状态表示本页查询上下文。默认读取后端真实当前标记，不按日期或第一条记录猜测。
- 手选历史或未来学期只修改内存中的查询上下文，不调用“设为当前”接口。选择在菜单及模块之间保持；选回平台当前学期后恢复自动跟随，管理页修改当前标记时同步更新。
- 顶栏与学年管理页共享含身份 id 的日历 Query key。正常令牌续期保留选择；重新登录、退出或切换身份清空。刷新后恢复登录并重新采用平台当前学期；选择失效时回退当前，无当前则提示选择。
- 空库显示“暂无学年学期”及联系管理员说明，不自动新建；加载失败显示重试入口。下拉保留滚动能力并隐藏滚动条，按钮、箭头与身份控件垂直居中。
- 学校业务通过共享 hook 获取成对的 `academicYearId`、`semesterId`，按各接口契约显式传入；无选择时返回空上下文，不拼接不同学年的 id，也不向无关接口自动追加参数。各学校业务页随对应任务接入。

### 学年学期页面实施约定（T-164）

- 入口为“平台管理 → 基础设置 → 学年学期”，列表展示学年、第一学期、第二学期、状态与操作，复用通用搜索筛选、排序、列设置和分页。
- 新建入口依据 `/academic-years/options` 的创建能力控制，空列表也可新建；不按角色名称或已有学年的动作推断。新建只提交起始年份，弹窗预览自动生成的两个学期及默认日期，新学年为“未开始”，不会自动成为当前。
- “编辑日期”先选择第一或第二学期，再提交该学期的起止日期与版本。接口按单学期更新，不将两次独立请求包装成一次整体保存。日期校验按 spec 08，错误保留输入，修改后清除对应字段的红色状态。
- “设为当前”只列出服务端允许切换的学期，并再次确认。跨学年切换以红字说明旧当前学年将关闭、历史日期只读且不能重新设为当前，确认按钮使用危险样式。同学年切换不关闭学年，不触发学校升年级或毕业。
- 行操作严格使用学期的 `allowedActions`；关闭学年与只读身份只显示“查看”。版本冲突保留草稿、禁用保存并允许重新加载；写请求携带版本、幂等键与取消信号，Query key 包含身份。
- 本页维护平台日历；顶栏学期选择器归 T-156，学校升级、预检查及撤回归 T-081，初始化当前学年归 T-140。

### 编号规则页面实施约定（T-164）

- 入口为“平台管理 → 基础设置 → 编号规则”，复用通用列表展示对象、规则、示例、重置周期与操作，支持对象筛选、关键字查询、排序、列设置及分页。
- 编号对象、默认前缀、流水位数和重置周期以 spec 11 与 contracts 为准。设计稿中的学号、教职工号、日期流水和每天重置仅为示意，不扩展当前已声明的六类规则。
- 修改弹窗采用两列布局，包含前缀、流水号位数、重置周期和只读的下一编号。预览取自后端当前已保存规则，明确标注保存后更新、不占用编号；不自行计算新前缀的下一可用流水。
- 修改按钮只根据行 `allowedActions` 显示，不提供新增、删除、手动取号或流水重置入口。字段和请求校验使用共享契约，写请求携带版本、幂等键和取消信号，Query key 包含身份。
- 保存失败保留输入；版本冲突禁用保存并允许重新加载最新配置、预览和版本。成功后更新真实列表并使用统一通知。加载、空列表、查询失败及无法生成预览分别处理。
- 通用表单 DOM 字段名采用命名空间，避免 `reset` 等契约字段覆盖原生表单方法；内存状态、错误映射和提交体仍使用原契约字段名。

## 6. 状态与数据

- zustand：令牌（内存）、当前身份、当前模块、当前学校、学年学期、已打开的页签；刷新页面时用 refresh 恢复。
- TanStack Query：key 统一为 `[identityId, schoolId?, 资源, 参数]`；切换身份时 `queryClient.clear()` 并清空页签。
- 401：先尝试刷新，失败回登录；403：提示无权限；409（90002）：提示刷新后重试。

## 7. 视觉

- 前端 UI 控件必须从 HeroUI 导入，禁止原生 HTML 控件替代，也禁止引入其他 UI 组件库。纯文本与非交互语义结构标签允许使用。
- 请求成功、失败的统一通知位于页面右上角，默认 2 秒后自动消失；关闭按钮使用圆形外框。字段校验错误由字段组件展示。

- HeroUI 3 + HeroUI Pro + Tailwind 4，浅色与深色主题；整体视觉参考 HeroUI Pro 的 Analytics 仪表盘模板。
- 布局与指标卡用 HeroUI Pro；表格、表单、弹层等业务组件用 HeroUI 3 开源组件。KPI、图表等 Pro 组件按子路径导入。
- 若最终不采购 HeroUI Pro，用 HeroUI 3 组件按相同结构实现 `AppLayout`、`Sidebar`、`KpiCard`，页面结构不变。
- 页面宽度 ≥ 1280 为主要设计尺寸，最小支持 1024。

## 8. 验收标准

- 多身份账号登录后进入选择组织页，选择后进入该身份的选择模块页，只看到可用模块；只有一个模块时直接进入该模块。进入模块后先看到工作台。
- 各身份看到的分组名和菜单名一致，只是数量不同。
- 在模块内切换组织后进入新身份的选择模块页，旧数据和旧页签不残留。
- 5.2 的每个流程都能从入口走到完成页，并能走通撤回、拒绝、失败重试等分支。
- 没有导出权限的用户看不到导出按钮，直接调用接口返回 403。
- 旧版浏览器访问显示升级提示页。
