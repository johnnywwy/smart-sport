D2角色与权限配置

目标是让管理员不用懂权限码也能配好角色：平台内置一套开箱即用的基础角色，绝大多数人直接选用；需要微调时“基于基础角色另存”，只改不同的几项。

原则做法管理员看到的

所有机构都能自建树形部门。部门“负责的单位”随机构类型变化：公司、代理商的部门负责学校，教育局的科室负责区县或学校，学校的年级组、学院负责年级或学院。四个选项在所有身份下含义一致，管理员只需学一次。没有建部门的机构，内置角色默认“本机构全部”，开箱即用。

多个角色时按权限码分别取范围：某权限码由哪些角色授予，就取这些角色中最宽的范围。例：角色 A（全校，学生查看）+ 角色 B（本部门初三，学生编辑）→ 查看全校、编辑只限初三；列表每行返回 allowedActions，前端按行显示按钮。做法与微软 Dynamics 365 按权限设置访问级别一致。

配置页会实时显示“按当前设置，该角色可以访问 23 所学校 / 6 个班级”，并提供“预览菜单”：以该角色视角看一遍侧栏与按钮，确认无误再保存。

设计点做法
和后台的关系独立应用 apps/mobile，共用契约包、登录、身份和权限；后台 apps/web 不做手机适配
菜单配置菜单表加 client 字段（admin / mobile），移动端 Tab 和首页入口也能在后台按身份配置
学生账号学校录入学生时自动生成账号（学校代码 + 学号），首次登录强制改密；学生身份的 ref_id 指向学校库中的学生
学生数据范围新增 self：只能读写本人数据，接口不接受任意学生 id
接口/api/m/* 按页面聚合，一屏一次请求，减少移动网络下的往返
运行环境手机浏览器、微信、钉钉内打开；支持加到主屏幕（PWA）；适配刘海屏安全区
后续家长身份、微信登录、消息推送；需要原生能力时再用 HeroUI Native 做 App，接口不变
