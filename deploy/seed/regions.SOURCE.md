# 全国行政区划数据来源

`regions.csv` 用于智慧体育云平台 T-030 的省、市、区县三级区划初始化。

- 上游仓库：[mumuy/data_location](https://github.com/mumuy/data_location)
- 上游提交：`34c02b29b2624e8ba06401aa76a5f942f79ae01f`（2026-11-02）
- 上游文件：`list.json`
- 上游版本标记：2026 年 4 月
- 许可证：MIT，Copyright (c) 2024 Haole Zheng
- 选择原因：约 3.2k GitHub Star、持续更新，并说明省市区数据来自民政部门、国务院公告和国家统计局

转换规则：

1. 只使用 `list.json` 的正式行政区，不使用含开发区、高新区和管理区的 `list2.json`。
2. 保留省、市、区县三级，按 GB/T 2260 六位代码生成 `parent_code` 和 `path`。
3. 为直辖市和省直管县级行政区补充树形中间节点，使所有区县都能通过“省 → 市级节点 → 区县”按级加载。
4. 上游说明港澳台下级代码属于自定义兼容码。项目 `regions.code` 要求国标区划码，因此不导入这些自定义下级，只保留 `810000`、`820000`、`710000` 三个标准省级代码。
5. 数据更新时必须固定新的上游提交，重新生成 CSV，并审查代码增删和行政区名称变化。

上游 MIT 许可证允许复制和修改数据。完整许可证见上游仓库的 `LICENSE`。

## 网页同步审核包

- `regions.review.json` 记录本次允许同步的版本、审核日期、上游固定提交和 CSV 的 SHA-256。网页仅加载该文件及对应 CSV；不接受客户端文件路径，不在线抓取并直接覆盖。
- 数据版本是上游标记的 **2026 年 4 月**，审核日期不代表区划数据更新到了该日期。更新数据时同时审查 CSV 差异及元数据，不能仅修改日期或自动重写校验值。
- 网页先预览并绑定审核包与数据库快照，确认时重新检查。撤销、改隶或重新启用旧码影响现有组织/范围时整批阻止。命令行导入也执行相同的影响保护，适用于初始化及经过审查的更新，不能作为绕过网页保护的入口。
